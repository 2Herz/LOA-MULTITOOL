계층 구조

위에서 아래로 의존해. 화면(Views)은 코어 인터페이스만 알고, 실제 구현(Services)은 Application이 만들어서 넘겨 줘. 칩을 누르면 아래 의존 관계도에서 그 모듈을 보여 줘.

툴(탭)별 구성

탭마다 매니저(ToolManager + Singleton)가 화면(View)과 모델(코어 인터페이스 → 서비스 구현)을 묶어. 공용 서비스는 ToolContext로 받아.

모듈 의존 관계도

왼쪽이 아래 계층이야. 모듈을 누르면 가져다 쓰는 모듈(→)과 이 모듈을 쓰는 모듈(←)이 강조돼. 점선은 .cpp에서만 쓰는 의존이야.

모듈을 하나 골라 줘.

지식 그래프(graphify): .graphifyrc가 .ixx를 C++로 읽게 하고, tools/Graphify-ModuleEdges.py가 export module · import 줄을 읽어 모듈 115개 · 모듈 의존 616개를 graphify-out/graph.json에 넣어. /graphify --update 뒤에 이어서 실행하면 graphify path "모듈A" "모듈B"로 의존 경로를 따라갈 수 있어.

실행 · 데이터 흐름

시작

  1. main.cpp wWinMain → Application
  2. 서버 점검 확인 (GistServerConfigChecker, 점검이면 안내 후 종료)
  3. API 키 읽기 (DPAPIKeyStore), 없으면 APIKeyDialog
  4. MainWindow + DX11Renderer 생성
  5. 탭 7개의 매니저 Initialize(ToolContext)
  6. 메시지 루프: Update → Render → 입력은 활성 탭으로

시세 조회 (스레드 규칙)

  1. 버튼 · 5분 자동 갱신(IntervalTimer)
  2. 호출 한도 확인 (RateLimitState, 분당 100회를 탭들이 공유)
  3. 백그라운드: BackgroundTask에서 Fetch만 (WinHTTP 요청 · JSON 해석)
  4. 화면 스레드: Update에서 IsReady → Apply → 표 갱신
  5. 401 → 키 재입력 안내 · 429/점검 → 알림

저장

  1. 모든 데이터는 %LOCALAPPDATA%\LostArkMultiTool
  2. JSONFileStore: 임시 파일 → 교체(원자적 저장) + .bak
  3. 읽기 실패 → 백업으로 다시 → 둘 다 실패면 빈 데이터 + 안내
  4. API 키는 DPAPI로 암호화 (현재 Windows 사용자만 복호화)
